So i like to write notes on my kindle in koreader, but it was pretty annoying to transfer them to my computer using SFTP or whatever. But then i found out about syncthing which syncs your files automatically! I havent used it much yet but I wanted to write down how I installed it because it was a bit complicated to understand.

my setup

  • I have a computer running fedora
  • A raspberry pi zero 2w running raspberry pi os 13 that i use as a server
  • ánd a jailbroken kindle paperwhite 10th generation (PW4) running a fairly recent firmware version i think? like 5.17 or something

installing syncthing

If you're on a normal system you can just look at the documentation. On fedora its just ‘sudo dnf install syncthing‘. On debian/raspberry pi os you need to add the ppa or something INSERT LINK.

...on a kindle

I found 2 options for koreader and 2 for KUAL i think. Since I only use koreader I chose the one that looked like it worked the most. I might try the other one some time since it deemd to have more features. I'll just show how to use syncthing.koplugin by AUTHOR.

Its not that complicated, just clone the repo LINK, move it to your plugins folder (/mnt/us/koreader/plugins normally). Then download LINK the syncthing binary for your kindle's architecture (ARM 32bit probably. idk how well it works for older/newer kindles), extract it and move the "syncthing" executable into the syncthing.koplugin folder.

connecting it all

So for some reason, instead of a cli or something reasonable, syncthing decided to use an http ui as the main way to control it. which is kind of annoying since 2 of the machines I want to set it up on dont have a web browser lol

But! There are (at least) two options to access the web ui from another, more capable device:

  1. Change the syncthing config to bind its web server to 0.0.0.0 (every ip address) instead of 127.0.0.1 (localhost, not accesible from other devices), which means other devices can connect to that port (i did not use this since it seemed cringe and insecure (literally me))
  2. Turns out ssh has a feature called tunnels which lets you kind of forward a port on a remote device to your local one. I dont really know how it works but its pretty nifty (this is the method I ended up using cuz it looked cool and based)
